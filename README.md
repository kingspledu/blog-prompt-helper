# 블로그 프롬프트 도우미

서식 규칙을 복사하고, 블로그 원문에 작성 지침을 붙여 복사하는 브라우저 도구입니다.

## 사용 방법

1. `index.html`, `gps-editor.js`, `gps-archive.js`, `image-library.js`, `draft-history.js`를 같은 폴더에 다운로드하여 브라우저로 엽니다.
2. **서식규칙복사** 버튼으로 규칙 내용을 복사합니다. 파일 첨부가 필요하면 **규칙 파일 다운로드** 버튼을 누르고 다운로드된 TXT 파일을 채팅창에 끌어 놓습니다.
3. 블로그 원문을 입력하고 **프롬프트 복사** 버튼을 누릅니다.

프롬프트 구성: 안내문 → 줄바꿈 10번 → 원문 → 줄바꿈 5번 → 작성 지침.

입력한 원문은 브라우저에서만 처리되며 서버로 전송하거나 저장하지 않습니다. 클립보드 접근이 제한되는 환경에서는 수동 복사 창을 제공합니다.

## 파일

- `index.html`: 스타일과 스크립트 및 프롬프트를 포함한 실행 파일
- `서식규칙.txt`: 채팅창 첨부용 규칙 파일

설치나 별도 서버가 필요하지 않습니다.

## HTML 결과를 블로그에 붙여 넣기

3번 섹션에 LLM에서 작성한 HTML 코드(HTML 코드 블록도 지원)를 붙여 넣으면 미리보기가 나타납니다. **블로그 내용 복사** 버튼을 누르고 블로그 편집기에 붙여 넣으세요. 코드 문자열 대신 서식이 포함된 HTML과 일반 텍스트가 함께 복사됩니다. 편집기가 지원하는 서식에 따라 붙여넣기 결과가 달라질 수 있습니다. 미리보기에서는 스크립트와 이벤트를 실행하지 않습니다.

## 이미지 GPS 위치정보 수정

4번 섹션에서 GPS 삭제 또는 입력한 위도·경도로 변경을 선택하고 이미지를 열면 자동으로 수정됩니다. 다운로드 버튼으로 별도 파일을 저장합니다. JPG·PNG·WebP(최대 30MB)를 지원하며, HEIC·GIF·TIFF는 지원하지 않습니다.

EXIF GPS를 수정하고 결과를 다시 읽어 검증합니다. 기존 GPS 태그의 값도 지우며, 중복 위치정보가 남지 않도록 XMP 메타데이터를 제거합니다. 이미지 픽셀 데이터는 재압축하지 않고 원본 파일은 덮어쓰지 않습니다. 다른 EXIF 정보는 유지됩니다. EXIF/XMP 이외의 위치정보나 촬영지 식별 정보까지 제거하는 기능은 아닙니다.

이미지는 서버로 전송되지 않고 브라우저에서만 처리됩니다. 위도는 -90~90, 경도는 -180~180 범위의 십진수입니다. GPS가 없는 이미지에도 좌표를 추가할 수 있습니다.

`gps-editor.js`는 이미지 컨테이너와 EXIF GPS 처리를 담당합니다. 웹페이지를 로컬에서 사용하려면 `index.html`과 같은 폴더에 두세요.

형식 참고: [PNG 규격](https://www.w3.org/TR/png-3/), [WebP 규격](https://developers.google.com/speed/webp/docs/riff_container).
## 여러 이미지와 주소·즐겨찾기

여러 파일을 선택하면 한 장씩 순서대로 처리하며, 실패한 파일은 표시하고 나머지 파일을 계속 처리합니다. 파일당 30MB, 선택한 파일 전체 300MB까지 지원합니다. 수정 방식이나 좌표를 바꾸면 이전 결과를 무효화하고 원본 파일부터 다시 처리합니다.

개별 다운로드, 전체 ZIP 다운로드, 순서대로 다운로드를 제공합니다. ZIP에는 성공한 이미지 파일만 포함하며, 여러 파일은 순번을 붙여 같은 이름의 파일도 구분합니다. 순차 다운로드가 브라우저에서 차단되면 여러 파일 다운로드를 허용하거나 ZIP을 사용하세요.

주소 또는 장소명을 검색하고 결과를 선택하면 GPS 좌표가 적용됩니다. 국내 주소 검색은 [Photon](https://github.com/komoot/photon) 공개 서비스를 이용하며, 검색 버튼으로 요청한 검색어만 외부 서비스에 전송합니다. 이미지 파일은 전송하지 않습니다. 요청 간격을 제한하고 같은 페이지에서 검색 결과를 메모리에 캐시합니다. 검색 서비스 장애나 OpenStreetMap 데이터에 없는 상세 주소는 검색되지 않을 수 있으므로 즐겨찾기 또는 직접 좌표 입력을 사용할 수 있습니다.

즐겨찾기: NLCS, BHA, KIS, SJA, 제주신화월드, 오설록 티뮤지엄, 생각하는 정원, 환상숲곶자왈공원. 좌표는 시설의 대표 지점이며 특정 건물이나 정문 좌표와 다를 수 있습니다. 출처 및 확인일(2026-10-07)은 아래 데이터와 화면의 지도 링크로 확인할 수 있습니다.

- 좌표 데이터: `gps-places.json` (페이지에도 포함되어 오프라인 선택 가능)
- ZIP 생성: `gps-archive.js` (STORE 방식, 이미지 재압축 없음)
- 지도 데이터: [OpenStreetMap 기여자, ODbL](https://www.openstreetmap.org/copyright)
- 오설록 좌표: [한국관광공사](https://data.visitkorea.or.kr/linkedview/2660802)

3번 섹션의 HTML 결과는 원본 코드의 정렬 설정과 관계없이 전체 가운데 정렬로 표시하고 복사합니다. 표 자체도 가운데 배치합니다. 붙여넣기 결과는 블로그 편집기가 지원하는 서식에 따라 달라질 수 있습니다.

## 장소명·좌표 파일명과 압축 다운로드

GPS 좌표 변경 모드에서는 이미지 파일명을 `순번_원본이름_장소이름_위도값_경도값.확장자`로 저장합니다. 좌표는 소수점 6자리로 표시합니다. 즐겨찾기는 NLCS 등 간단한 이름을, 주소 검색은 장소 이름을 자동 입력하며, 이름 입력창에서 원하는 이름으로 바꿀 수 있습니다. 이름을 입력하지 않으면 `직접입력`을 사용합니다.

파일명에 사용할 수 없는 문자는 정리하고 UTF-8 길이를 제한합니다. GPS 삭제 모드에서는 좌표와 장소명 대신 `GPS삭제`를 사용합니다. 원본 파일명은 유지하므로 원본 이름에 이미 포함된 정보는 그대로 남을 수 있습니다.

**전체파일 압축 다운로드 (ZIP)** 버튼은 성공적으로 수정된 전체 이미지를 한 ZIP으로 저장합니다. 압축파일명에도 장소명·좌표·이미지 수를 넣고, ZIP 내부 이미지도 같은 이름 규칙을 사용합니다. 개별 다운로드와 순차 다운로드도 그대로 제공합니다.
## 자주 쓰는 이미지와 전화번호

3번 섹션의 이미지 보관함에 명함 등 JPG·PNG·WebP 이미지를 여러 장 저장할 수 있습니다. 파일당 10MB, 보관함 전체 100MB까지 지원합니다. 이미지마다 블로그 삽입 위치를 사용 안함·맨 처음·맨 끝·처음과 끝 중에서 선택하며 여러 이미지를 함께 사용할 수 있습니다. 별도의 GPS 수정에 불러오기 버튼으로 같은 이미지를 4번 섹션에서도 사용할 수 있습니다.

이미지별 전화번호 또는 별도의 연락처 번호를 입력하면 `tel:` 링크로 삽입합니다. 별도의 번호도 처음·끝·양쪽 중에서 위치를 선택할 수 있습니다. 번호만 삽입하거나 이미지와 함께 사용할 수 있습니다. 이미지, 이름, 위치, 전화번호는 IndexedDB에 저장되어 같은 브라우저에서 다시 방문해도 복원됩니다. 다른 기기와 동기화되지 않으며 사이트 데이터를 삭제하면 사라집니다. 저장 기능은 공개 웹주소에서 사용하는 것을 권장합니다.

블로그 내용 복사는 선택한 이미지와 전화 링크를 포함합니다. 붙여 넣는 블로그 편집기가 이미지 복사를 지원하지 않으면 보관함의 이미지 다운로드 버튼으로 파일을 받아 직접 첨부하세요. 원본 이미지의 GPS를 바꾸려면 4번 섹션에서 수정한 파일을 다운로드해야 합니다.
## 입력 자동 저장과 히스토리

원문·HTML 코드·전화번호·GPS 설정과 이미지 삽입 설정을 입력값이 바뀔 때마다 즉시 자동 저장합니다. 입력을 2초간 멈추면 히스토리를 만들고, 작업 중에는 30초 간격으로 변경된 버전을 확인합니다. 페이지를 벗어나거나 다른 탭으로 전환할 때도 저장합니다. 생성 후 24시간 이내의 최근 50개 기록을 날짜와 내용 미리보기로 선택하여 불러올 수 있습니다. 각 기록은 생성 시각을 기준으로 24시간이 지나면 목록과 저장 기록에서 제거하며, 페이지를 열어 둔 동안에도 만료를 확인합니다. 마지막 자동 저장 입력은 만료와 별도로 유지합니다. 지금 저장 버튼으로 수동 기록을 남길 수 있습니다. 변경 없는 버전은 중복 기록하지 않습니다.

입력값 리셋하기는 리셋 직전 히스토리를 남긴 후 입력값과 GPS 작업용 파일을 비우고 이미지의 블로그 삽입을 해제합니다. 저장 이미지와 히스토리는 유지합니다. 히스토리 복원은 현재 이미지를 보관함에서 찾으며, 이미 삭제한 이미지 자체를 되살리지는 않습니다. GPS 작업용 파일은 자동 저장하지 않으므로 다시 선택해야 합니다. 기록은 해당 사이트의 같은 브라우저에만 저장되며 저장 공간이 부족하면 오래된 히스토리부터 정리합니다. 사이트 데이터 삭제 시 기록도 삭제됩니다.
## 입력값 JSON 저장·불러오기

입력값 JSON 다운로드 버튼으로 현재 원문·HTML·전화번호·GPS 설정·이미지 이름/전화번호/삽입 설정을 파일로 저장합니다. 저장한 입력값 JSON 불러오기에서 이 파일을 선택하면 검증 후 입력값을 복원하고 자동 저장합니다. 불러오기 전 현재 입력은 히스토리로 남깁니다. 형식 또는 좌표가 잘못된 JSON은 입력을 변경하지 않고 오류를 표시합니다. 파일 크기는 10MB까지 지원합니다.

JSON에는 이미지 파일 자체와 히스토리가 포함되지 않습니다. 이미지 설정은 같은 보관함에 해당 이미지가 있을 때 적용됩니다. JSON 파일은 24시간 만료와 무관하게 보관하고 나중에 불러올 수 있습니다.
자동 저장·입력 히스토리 패널은 페이지 맨 하단에 기본으로 접혀 있습니다. 접힌 상태에서도 자동 저장과 히스토리 기록은 계속 동작합니다.

## 공개 이미지 업로드 준비 브랜치

로그인 없는 공개 업로드 서버와 이미지 전용 저장소를 구성했습니다. 인증 연결 대기 상태로 실제 업로드는 아직 활성화되지 않았습니다. 서버 설정·인증 범위·제한·운영 안내는 [upload-server/README.md](upload-server/README.md)에 있습니다. 공개 페이지에는 인증 연결 및 실제 업로드 검증 이후 반영합니다.

## Supabase 전환

사용자 선택에 따라 공개 이미지 업로드는 Supabase로 전환합니다. 프로젝트 주소와 Publishable key 및 저장소 정책 적용 대기 중이며 공개 메인 페이지에는 아직 반영하지 않았습니다. 연결 절차와 설정 SQL은 [supabase/README.md](supabase/README.md), [supabase/setup.sql](supabase/setup.sql)에 있습니다. 이전 upload-server 코드는 미사용 GitHub 방식의 참고 자료입니다.
